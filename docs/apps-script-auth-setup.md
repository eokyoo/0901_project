# Google 스프레드시트 회원가입·로그인 연결

## 1. Apps Script 코드 설치

1. 사용할 Google 스프레드시트를 엽니다.
2. `확장 프로그램 → Apps Script`를 선택합니다.
3. 기본 `Code.gs` 내용을 모두 지우고 프로젝트의 `google-apps-script/Code.gs` 내용을 붙여넣습니다.
4. 새 웹 앱 배포 후 첫 요청에서 `Users`, `Sessions`, `Posts` 시트와 서버 비밀값이 자동 생성됩니다.
5. 미리 권한을 승인하거나 시트를 먼저 만들고 싶다면 Apps Script 편집기에서 `setup` 함수를 한 번 실행해도 됩니다.

`Users`에는 사용자 정보와 비밀번호 해시가 저장됩니다. `Sessions`에는 로그인 토큰의 해시와 만료 시각이 저장됩니다. `Posts`에는 작성자 ID, 제목, 카테고리, 요약, 본문과 작성·수정 시각이 저장됩니다. 스프레드시트 공유 설정은 비공개로 유지하세요.

## 2. 웹 앱 배포

1. Apps Script 오른쪽 위 `배포 → 새 배포`를 누릅니다.
2. 유형은 `웹 앱`을 선택합니다.
3. 실행 사용자는 `나`, 액세스 사용자는 블로그 방문자가 접근할 수 있는 항목을 선택합니다.
4. 배포 후 `/exec`로 끝나는 웹 앱 URL을 복사합니다.
5. 프로젝트의 `js/config.js`에서 `PASTE_YOUR_APPS_SCRIPT_WEB_APP_URL_HERE`를 복사한 URL로 교체합니다.

Apps Script 코드를 수정한 뒤에는 `배포 → 배포 관리 → 수정 → 새 버전`으로 다시 배포해야 변경사항이 반영됩니다. `/dev` 주소는 개발 테스트 전용이므로 블로그에는 `/exec` 주소를 사용하세요.

## 3. 확인 순서

1. `signup.html`에서 테스트 계정을 만듭니다. 첫 요청은 자동 초기화 때문에 평소보다 조금 더 걸릴 수 있습니다.
2. `Users` 시트에 이메일, 이름, 해시값이 추가됐는지 확인합니다.
3. `login.html`에서 같은 계정으로 로그인합니다.
4. 브라우저 개발자 도구의 콘솔에 오류가 없는지 확인합니다.
5. 로그인 후 `write.html`에서 글을 발행하고 메인·전체 글·상세 페이지에 표시되는지 확인합니다.
6. `profile.html`의 `내가 쓴 글`에서 수정과 삭제가 작성자 본인에게만 동작하는지 확인합니다.

## 보안 참고

- 비밀번호 원문은 저장하지 않습니다.
- 서버 비밀값은 Apps Script의 Script Properties에만 저장됩니다.
- 로그인 세션은 7일 후 만료됩니다.
- 이 구조는 개인 블로그·수업용 소규모 프로젝트에 적합합니다. 결제나 민감정보를 다루는 서비스에는 Firebase Authentication 같은 전문 인증 서비스를 사용하세요.

## 테스트 데이터 정리

기존 연결 테스트에서 만들어진 데이터는 Apps Script 편집기에서 `cleanupDummyData` 함수를 한 번 실행해 정리할 수 있습니다. 이 함수는 제목·요약·본문이 미리 지정된 테스트 게시물과 `codex.*@example.com` 형식의 테스트 계정만 삭제합니다. 공개 웹 API에는 연결되어 있지 않으므로 스프레드시트 소유자만 실행할 수 있습니다.

## 브라우저 캐시와 임시 저장

- 게시글 목록·상세·내 글은 브라우저의 `localStorage` 캐시를 먼저 표시하고 Apps Script 데이터를 백그라운드에서 갱신합니다.
- 새 글과 수정 중인 글은 계정과 게시글별로 분리하여 입력 후 자동 임시 저장합니다.
- 발행·수정·삭제가 완료되면 관련 게시글 캐시는 자동으로 무효화됩니다.
- 공용 컴퓨터에서는 사용 후 반드시 로그아웃하고 브라우저 사이트 데이터를 삭제하세요.
